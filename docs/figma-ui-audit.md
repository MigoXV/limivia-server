## 业务与交互检查

- 导航支持来自本次 `discovery.operations/resources`，文件使用实际的 `storage.*` 能力。设计示例中禁用的入口不会被照抄成某个 profile 的固定限制。
- 配置草稿和侧栏选中均属于前端视图，不创建资源。点击当前主导航保留正在编辑的草稿；切换到另一资源仅改变当前选择，不重新创建资源。
- 资源列表来自当前连接代次的快照。更换连接或固件身份后旧选择失效；占用来源不等于当前页面取得了控制。
- 未创建资源、过期状态、未知结果和其他来源占用保持明确文字；不显示成已熄灭。LED 的开关、呼吸、读取、模式切换确认及权限仍使用原有业务链路。
- 侧栏中部独立滚动，顶部上下文与底部辅助入口保留；正文和首页能力表支持键盘滚动。650px 以下改为顶部导航网格；窄屏和 200% 放大检查无水平溢出。
- “引脚与占用”按新版放在外设等设备页面的辅助区，首页和流程页面可从“固件与能力”弹窗访问。主题切换保留在底部版本行；这是为保留原有操作补充的小型文本入口。
- 设计的固件、资源、波形与流程为示例。既有业务表单继续按设备能力生成，不将示例数据当作设备输出或物理测量。LED 标注保留“输出示意 · 非物理测量”。

## LED 反馈抖动修复

复现了 LED 开关时资源通知短暂将快照标记为 stale：原页面随即插入顶部“设备状态待同步”提示条，快照完成又移除。逐帧记录显示 LED 面板 y 在 196 与 293 之间反复切换，造成 97px 位移。相关证据保存在 `artifacts/led-feedback/before.json`。

修复后，正常同步在既有顶栏显示“同步中”，LED 操作在固定 40px 双行反馈区显示；失败同样在该区域持续保留，下一次提交替换反馈。超长文字可在区域内滚动并通过键盘访问，不在按钮旁追加错误块。主操作、读取和关闭按钮固定宽度，避免“提交中”文本改变操作行换行。真正的断线、连接或协议错误仍保留明确提示，不将设备旧数据说成新确认结果。

Figma 已同步主设计页的 70 个 LED 状态与 LED 详情页的 28 个反馈区域，使用相同固定占位。主画板、已点亮、点亮确认中、熄灭确认中及未知结果的面板均为 y=196/h=244，操作行均为 y=299；原型跳转继续使用原位状态，未新增自动消失弹层。说明文字位于主设计页 `2189:8433`，两套主题及 1280×720 变体均已更新。

新增回归逐帧记录 1280/1440 两种宽度、两套主题下连续三轮开关，断言面板位置、高度和按钮位置差值小于 0.5px，并确认快照同步确实发生。另验证错误持续显示、修正后可重试、真正断开时仍有提示。修复后的同场景记录 `artifacts/led-feedback/after.json` 只有同一个几何状态，位移为 0px。

本次抖动修复验证：Python 129 项、前端单元测试 9 项、完整 Playwright 53 项通过，Ruff、ESLint、生产构建通过。运行实例已使用最新构建，通过 USB 现有连接只读查询确认固定反馈区高 40px 且不插入顶部同步提示，记录在 `artifacts/led-feedback/live-check.json`，没有改动原有输出配置。

## LED 最近确认值与全局文字稳定显示

进一步修正了普通 `stale` 同时驱动多个无关标签的问题：资源快照待同步不等于固件能力未识别，也不等于 LED 的历史确认值消失。侧栏可用性、能力摘要和协议验证文字已独立于普通快照刷新；连接保持“已连接”。“操作记录”入口只显示固定文字，进行中数量移至记录弹窗。

LED 主状态改为“设备最近确认输出”，执行期间保留最近读回的输出及示意。按钮立即禁用以防重复提交，但保留操作前文案。新的输出在命令完成、状态读回及快照同步后显示；进度、错误和持续超过 300ms 的待同步情况只在既有 40px 反馈区展示。没有确认值时保持未知，断线、未知结果、资源关闭或更换实例会使旧确认值失效；更换连接、启动标识和资源实例均有独立作用域。此记忆是前端展示投影，不是目标输出，也不放宽写入所需的控制权和新鲜快照条件。

LED 的写入、已有资源状态读取和关闭不再调用全量能力重读入口，使用后端已有的快照同步。无资源时用户主动点击“读取状态”，仍使用既有刷新入口重新核对设备；没有新增硬件协议、HTTP/WebSocket 字段或 SDK 事件模型。

Figma：主设计页 70 个原有 LED 状态统一最近确认标签，开关确认中保留来源 On/Off 示意及按钮文案，读取中保留已知输出；详情页 28 个状态同步标签和开关示意。另增加首次点亮确认中的两主题状态 `2199:8711`、`2199:8901`，从无资源入口进入时显示未知而非假定已熄灭。现有 72 个首页反馈槽均保持 40px。

验证从几何检查扩展到整段文字序列：两主题、1280/1440 连续三轮开关，逐帧检查侧栏和摘要不变、连接保持已连接、记录入口没有瞬时数字，LED 标题严格按“熄灭→点亮→熄灭”交替，不插入等待或未知标题，也没有多余往返。另覆盖长任务保留上次值、错误失效与显式读取恢复；单元测试覆盖首次未知、断线、故障、关闭、启动/代次/实例变化及 PWM 确认条件。

本轮 Python 129 项、前端单元测试 14 项、完整浏览器 54 项通过，Ruff、ESLint、生产构建通过；加强标题切换顺序检查后，相关 7 项浏览器回归再次通过。运行实例已使用最新构建，USB 只读查询的逐帧记录也确认全局文字稳定、现有资源定义未改变；没有接管原有输出。记录与设计截图位于 `artifacts/led-confirmed-state/`。

## 外设常驻目录与详情

外设调试改为内容区左侧 240px 功能目录、右侧详情，删除“外设目录 / 板载 LED”切换和目录行内的“打开”按钮。每行最小高 56px，整行支持鼠标、Enter 和 Space 选择，使用主侧栏相同的选中、悬停 Token 与过渡。副标题使用主文字 Token，避免白垣选中背景与过渡过程的对比度不足。固件未提供的能力集中到目录底部“当前不可用”组，默认折叠，展开仅展示名称与原因。

目录按 SDK 的实际能力报告生成，不根据 profile 名称推测功能。已确认板型与 GPIO13 输出能力都满足时，板载 LED 作为普通功能默认选中，详情直接复用首页 `LedPanel`；否则优先第一个可用功能。LED 根据自身容器宽度重排定位、最近确认输出和控制区，保留固定反馈及此前防闪烁行为。选择功能只改变视图，不提交硬件命令；重复选择保留草稿。现有资源仍在主侧栏导航，详情按资源 ID 与实例精确匹配，创建成功后读取实际实例再进入详情。

桌面工作区固定，目录与详情各自滚动，标题和操作记录入口不随内容移动。删除内容区重复的已创建资源侧栏，原始一致快照折叠保留在详情中。320 / 768px 和 200% 放大采用上下布局，保留目录局部滚动和详情可达性。
